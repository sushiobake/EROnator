## ゴール

あなたの仕事は、**各作品を「タグ済」または「人間による確認が必要」のフォルダに移動すること**である。タグ付けはしない。フォルダを移動させるには、必ず上記 5 の apply コマンドを実行すること。

---

## 目的

作品に**正確で差別化できるタグ**（通常タグ＋キャラタグ）が付いているかどうかを見る。  
「タイトル＋コメント」から得られる情報が、**公式タグと付け加えたタグ**で過不足なく反映されているかを確認する。

---

## 入力（1作品あたりのデータ）

fetch の出力は `{ allTags: { s, a, b }, works: [...] }`。`works` の各要素に以下がある。

- **workId**: 作品ID
- **title**: タイトル
- **commentText**: 作品コメント（あらすじ等）全文
- **derivedTags**: 現在の DERIVED（付け加えたタグ）の表示名の配列
- **officialTags**: 現在の OFFICIAL（公式タグ）の表示名の配列（既存S＋追加Sの両方を含む）
- **characterName**: 現在のキャラ名（1人分、無ければ null）

**1回の入力は最大100件まで。** 100件を超える場合は分割すること。

---

## 毎作品で必ず確認する3項目

以下は**全作品について漏らさず**行う。

1. **タイトル照合**
   - タイトルに含まれる語（合宿、催眠、JK、人妻、総集編、寝取られ など）が、**officialTags と derivedTags で過不足なく反映されているか**。
   - 余計なタグがないか、必要なタグが抜けていないか。

2. **各タグの根拠**
   - derivedTags の**それぞれ**に、タイトルまたは commentText に明確な根拠があるか。
   - 根拠が弱い・推測だけのタグは指摘する。根拠がなければタグが0個でもよい。

3. **キャラタグ（characterName）**
   - commentText に**登場人物の名前**が明記されていれば、代表1人が characterName に入っているか。書いてないときは null でよい。
   - **作品タイトルはキャラ名ではない。** タイトル文字列を characterName に入れていないか。

---

## チェックの手順（この順で実行する）

各作品について、**次の3段階**で行う。

### ステップ1：タイトルを読んでタグとの対応を確認する

- **まずタイトルを読む。** タイトルに出ている語（合宿、催眠、JK、人妻、総集編、寝取られ など）を抽出する。
- officialTags と derivedTags を合わせて、それらが**過不足なく**カバーされているか確認する。
- **不足**：タイトルにある重要な語がタグに無い → 指摘する（追加推奨を tagChanges.added に。**追加前に officialTags に既に同じ語が無いか確認すること**）。
- **余分**：タグにあってタイトル・コメントに根拠が無い → 指摘する（tagChanges.removed に）。

### ステップ2：各 derived タグの根拠を確認する

- derivedTags の**1つ1つ**について、タイトルまたは commentText のどこに根拠があるか確認する。
- 根拠が無い・推測だけのタグは指摘する。指摘した場合は tagChanges.removed に含める。
- checkReasoning の「各タグ根拠」に、各タグの根拠を簡潔に書く（サボらない証拠）。

### ステップ3：キャラタグを確認する

- commentText に登場人物の名前が出ていれば、characterName に代表1人入れているか確認する。
- 名前が無ければ null でよい。
- **タイトル文字列を characterName に入れていないか**確認する（よくあるミス）。
- checkReasoning の「キャラ」に結果を書く。

---

## チェック観点（補足）

### 追加推奨の注意

**tagChanges.added は既存S/A/Bの語のみ。** 新規タグは tagSuggestions.newProposal に書く。  
**tagChanges.added を出す前に、officialTags に同じ語が既に含まれていないか必ず確認すること。** 含まれている場合は追加提案に含めない。

**【重要】有名タグリスト（使用禁止）について：** このリストは**タグ付け**（matchedTags／suggestedTags）用のルールであり、**チェックには適用しない**。不足として追加推奨すべきタグがそのリストに含まれていても、tagChanges.added に含める。「使用禁止だから追加しない」という判断は禁止。

### シリーズ

- タイトルに**数字（2, 3, 4 など）**や**「続編」「総集編」「編」**などがあれば、シリーズ系タグが1つ付いているか。
- 根拠がなければシリーズ系タグは不要。

### 付けてよいタグ・付けてはいけないタグ

- **付けてよい**: タイトル・あらすじに**明記**されている語。背景だけの語（出張・同窓会・夏休みなど）も、意味がある場合が多いので付けてよい。
- **付けてはいけない**: メタ情報だけ、汎用語、主軸でない設定だけ、視点タグ（明記がない限り）、曖昧・広義すぎるタグ。

### 語彙・表記

誤字・略語・造語（眠姦→睡眠姦、催●→催眠など）は指摘する。

---

## タグ修正をする場合

- あなたがタグを**修正してよい**。
- 修正した場合は、**追加したタグ**と**削除したタグ**を、**tagChanges** に私にわかるように表記する。追加は**既存S/A/B**から選ぶ。
- 既存S/A/Bに無い新規タグが必要だと思う場合は、**tagSuggestions.newProposal** に1個まで書く。
- 修正した作品は**人間による確認が必要**として出力する。

---

## 出力形式（全作品で必須）

**作品ごとに** 次の形式で返す。**checkReasoning は全作品で必須。** タグ済・人間による確認が必要のどちらでも省略禁止。

```json
{
  "workId": "d_xxxxxx",
  "title": "作品タイトル",
  "result": "タグ済",
  "checkReasoning": {
    "タイトル照合": "タイトルに出ている語（〜）がタグにどう反映されているか。不足・余分があれば記述",
    "各タグ根拠": "derivedTags 各1つについて、タイトルまたはcommentText上の根拠を1行で",
    "キャラ": "commentTextに名前があればcharacterNameに入っているか。タイトルをキャラ名に入れていないか"
  }
}
```

**人間による確認が必要の場合の例:**

```json
{
  "workId": "d_xxxxxx",
  "title": "作品タイトル",
  "result": "人間による確認が必要",
  "checkReasoning": {
    "タイトル照合": "…",
    "各タグ根拠": "…",
    "キャラ": "…"
  },
  "issues": ["指摘1", "指摘2"],
  "tagChanges": {
    "added": ["追加したタグ名"],
    "removed": ["削除したタグ名"]
  },
  "tagSuggestions": {
    "newProposal": "新規提案タグ（既存S/A/Bに無い語。0〜1個）"
  }
}
```

- **workId**: 作品ID（入力のそのまま）
- **title**: 作品タイトル（入力のそのまま。照合用に省略しない）
- **result**: 「タグ済」または「人間による確認が必要」
- **checkReasoning**: **全作品で必須。** なぜその判定にしたか、上記3項目を簡潔に書く。サボらず確認した証拠として私が参照する。
- **issues**（人間による確認が必要の場合）: 観点ごとの指摘。簡潔に。
- **tagChanges**（既存タグの追加・削除を提案した場合）:
  - **added**: [ 既存S/A/Bから追加したタグ名のリスト ]
  - **removed**: [ 削除したタグ名のリスト ]
- **tagSuggestions**（新規タグを提案する場合）:
  - **newProposal**: 既存S/A/Bに無い新規タグ（0〜1個。文字列）

**省略禁止**: checkReasoning は全作品で必須。修正したタグは必ず added / removed に書く。各作品に workId と title を必ず書く。

---

## 提出前チェック（各作品）

JSON を出す前に、その作品について以下を確認する。

- **タイトルに出ている語をタグでカバーしているか確認したか**
- **derivedTags の各1つに根拠があるか確認したか**
- **キャラタグ（名前があれば characterName、タイトルをキャラ名にしていないか）を確認したか**
- **checkReasoning を省略していないか**

**提出直前**: ①全 workId が出力にある ②tagChanges.added は allTags の s/a/b から ③checkReasoning は全作品で必須

---

## 出力件数（漏れ防止）

- **返す JSON 配列の件数は、必ず入力の作品数と一致させること。** 1件でも書き漏らすと反映時に不整合になる。
- **出力し終えたら、入力に含まれる全 workId が出力配列に1回ずつ含まれているか照合すること。** 漏れがあれば追加してから返す。

## フォルダを移動するための反映（上記「実行順序」の 3・4・5。必ず実行）

JSON を出したあと、**この 3 つをしないとフォルダは動かない。**

1. **返した JSON 全文を会話に貼り付ける。** 私が内容を確認できるようにする。
2. **返した JSON を `data/chatgpt-export/check-pending.json` に保存する。**（ファイル名は固定）
3. **以下をプロジェクトルートで実行する。**
   ```bash
   npx tsx scripts/apply-check.ts
   ```

**apply-check を実行しない限り、作業は完了していない。書いたら即実行すること。**
