# 本番プレイ履歴で見えた「確率分布が薄い」現象メモ

更新日: 2026-04-13

## 要約

2026-04-13 時点の本番プレイ履歴サンプル（9件）では、FAIL_LIST 到達時の `failListContext.topCandidates[0].probability` が **約 0.9%〜8.6%** にとどまるケースが多く、システムが「この1作品だ」と確信できないまま REVEAL を繰り返し、最終的に失敗リストに落ちるパターンが観測された。

これは**アルゴリズム単体のバグ**というより、**母集団の大きさ・質問の情報量・タグの付き方・（場合によっては）正解がDBにいない**などが重なった結果として起こりうる。

## 想定される構造的要因

1. **回答パターンが多数の作品に共通する**  
   まとめ質問（恋愛・学園・制服など）の組み合わせで、候補の大半が同方向に動き、1作品への収束が遅い。

2. **NO が続くと消去法になり差がつきにくい**  
   SOFT_CONFIRM などで NO が続くと、残った集合に確率が分散しやすい。

3. **正解がDBにない／タグが足りない**  
   その場合、質問はノイズに近くなり、分布は平坦化しやすい。

4. **候補数が多い中でのベイズ更新**  
   `gameRegistered` かつ手描きフィルタ後も母数が大きいと、同じ質問数でもトップ確率は上がりにくい。

## 今後の検討方向（即時対応ではない）

- 管理画面の **プレイ履歴リプレイ** で、分析対象作品を指定し**順位・確率・有効候補数の推移**を見る（実装済みの機能を活用）。
- **Information Gain** や質問タイプ別の効きを、リプレイやシミュレーションで定量化する。
- SUCCESS ケースとの比較で「何問目で確率が伸びたか」を見る。
- まとめ質問のカバー率が極端なタグのリバランス（データ・設計両面）。
