# 推薦モード（稲荷さんに同人誌を推薦してもらう）仕様

おまけモードだが重要。ゲーム体験として楽しめる程度には実装する。

---

## 前提：プレイモードとの共通化

**以下はエロネイターの「プレイ」で使っているものをそのまま使う。変更しない。**

- 背景
- ホワイトボード（白板）
- キャラクター
- **質問に答える → thinking → 次の質問** の流れ（構造はまったく同じ）

**変えるのは次の3点だけとする。**

- 質問の文言（「当てる」用 → 「好みを聞く」用）
- 答え方（単一選択 → 複数選択など）
- 白板のサイズ（必要に応じて）

---

## ① おすすめ選定の仕方（アルゴリズム）

### プレイモードと違う点

- **ハードコンフィム（タイトル・作者を使った選定）**  
  → 推薦では使わない。する必要がない。
- **ソフトコンフィム**  
  → 推薦では量が膨大になりすぎるため、ほぼ不可能。使わない。

### 採用する方向性

| 要素 | 方針 |
|------|------|
| **Sタグ** | エロネイターをそのまま使う。Sタグによる選定は既存と同様。 |
| **有名か無名か** | 推薦モード専用の軸として使う（人気度・露出の調整など）。 |

### 補足として検討可能なもの

- **マッチ数でソート**  
  選んだタグに何個ヒットしたかで並べる（既存の matchScore に近い考え方）。
- **「少し意外」を混ぜる**  
  一致度だけでなく「人気は中くらいだが一致度が高い」を1〜2本混ぜる（隠れた名作の延長）。有名/無名の軸と組み合わせやすい。

### 結論（①）

- Sタグ ＋ 有名/無名 ＋（余裕あれば）マッチ数・少しの「意外さ」で十分。
- アルゴリズムはこの範囲で確定とする。

## ② 質問と回答

### 制約

- **最大10問**  
  長すぎると飽きるため、質問数は10問までとする。

### 悩んでいるポイント（未解決）

**「正確に推薦する」だけが目的なら、最初から646個のSタグを全部見せて選ばせればよい。**

しかし目的はそれだけではない。**「推薦してもらう、という体験」** が大事である。  
そのため、単純に「全タグ一覧から選ぶ」だけの設計にはしない。

**現状のジレンマ：**

1. **質問を固定（A案）**  
   - 実装は簡単。
   - ただし「1問あたり10個のタグ」にすると、10問×10＝**100タグまでしか扱えない**。
   - Sタグは646個あり、0作品を除いても数百個ある。100個に押さえると「それじゃない」が多く、ややこしい。

2. **問1＝ジャンル、問2＝プレイ、問3＝シチュ…（カテゴリ固定）**  
   - 一見よさそうだが、「それぞれ10個のタグ」とすると上記と同じ上限問題。
   - さらに **Sタグを正確にジャンル分けする** ことは、それ自体が難しい（メタデータ・運用負荷）。

3. **回答に応じて質問を変える（B案）**  
   - エロネイターのシステムを流用すれば理論上は可能。
   - ただし推薦用に状態管理・質問選択を組み直すコストが大きい。

**理想のイメージ：**

- ある程度の質問は固定しつつ、**「包括的な質問」** を用意する。  
  例：「この中であなたがこだわりたいのはどれ？」のように、複数タグから選ばせる問い。
- 一方で、タグ総数（数百）と「1問あたりのタグ数」「問の数」のバランスがまだ決まっていない。

### 検討メモ（②の方向性）

- **「10問」＝画面ステップ数の上限** とし、「1問＝10タグ」は必須としない（問ごとに可変でもよい）。
- ジャンル分けは **既存の tag.category でざっくり** に留め、正確な分類は必須にしない。
- **「推薦してもらう体験」** を損なわない形で、  
  「何を聞くか」「どう見せるか」「固定と適応のどれをどこで使うか」を詰める必要がある。

### ② 設計案（いったん doc に固定。実装前にもっと詰める）

**目標:** その人のコア性癖 2〜4 個を見つける。

#### 前半（Q1〜Q3）: 方向性の3択 → さっと答える

| Q   | 質問           | 選択肢（3択）              |
|-----|----------------|----------------------------|
| Q1  | 雰囲気は？     | 甘め / 激しめ / 切なめ     |
| Q2  | 何にこだわる？ | シチュ / プレイ / キャラ   |
| Q3  | 作品の知名度は？| 有名 / 隠れた名作 / 中間   |

→ タグプールを 646 → 100〜150 に絞る。  
※ 1〜2ページにまとめて表示する運用も可（例: 3問を1ページ、あと6問 or 2ページで4問ずつなど）。

#### 後半: コア性癖を見つける

- **案A: ペア比較**  
  1問でタグ2個を並べて「どっちが好き？/ どっちも / どっちでもない」の4択。  
  懸念: タグによってはペアにふさわしくないものもある。
- **案B: 好き嫌いスワイプ**  
  1問1タグで「好き / 普通 / 嫌い」。  
  懸念: タグ総数に対して少なすぎる。
- **採用案: 動的10タグ ＋ 好き/嫌い/無関心**
  - 1問あたり10タグ提示。各タグに **好き / 嫌い / 無関心（デフォルト）** をつけられる。
  - **マイナー性癖にたどり着く鍵:** 前の回答で「好き」を選んだタグと**共起率が高い**タグを次の問に優先して出す、という案があったが、実データで検証した結果は以下。

#### データ検証の結果

- 使えるタグ: off_ + tag_ で 634 個（作品数10以上）。char_ は推薦では無視。
- 共起は強い（例: あるタグの共起上位 71.5%, 63.8%）。  
  **ただし** 共起上位はメジャータグ同士に偏る。マイナータグ（作品数10〜50）はメジャーとの共起率が低く、共起ランキングだけでは出てきにくい。

#### 現実的な落としどころ: 共起ランキングではなく「作品群ドリルダウン」

- **前半:** 方向性で絞る（Q1〜Q3、1〜2ページ）。
- **中盤:** メジャータグ10個を提示 → 好き/嫌い/無関心（2〜3問）。
- **後半:** **中盤で「好き」を選んだタグが付いている作品群が持つタグ**のうち、**まだ提示していないもの**を10個提示。  
  → **共起率ランキングではなく「好きタグを持つ作品群のタグ一覧」から未提示を出す**。  
  これなら作品数15のマイナータグでも、好きタグの作品群に含まれていれば出てくる。
- workTagMatrix 等で「タグ → workId 一覧」「workId 群 → タグ一覧」を用意すれば実装可能。詳細は実装前に詰める。

**まとめ（②）:** 前半 1〜2ページ（方向性）＋ 中盤 2〜3問（10タグ×好き/嫌い/無関心）＋ 後半（作品群のタグから未提示を補充）。合計10問以内。②の内部ロジック（タグプール絞り・動的提示）は実装の後段で行う。

### 結論（②）

- 最大10問は維持。
- 上記「② 設計案」をいったん仕様として doc に固定。実装前にもっと詰める。  
- 実装フェーズでは **表面上だけ**（Stage・1問だけ・thinking・結果表示）を先に作り、②の内部（タグ絞り・動的10タグ・好き嫌い集計）はあとから実装する。

## ③ 結果の表示

### 方針

- **最大10作品** を表示する。
- **横2列 × 5個** のレイアout（2列で5個ずつ）。
- エロネイター本編の **「おすすめ」** のUIを流用する。  
  現状は縦並びになっているが、レイアウトを **横2列** に変更して、推薦モードでも同じおすすめコンポーネントを使う。

### 結論（③）

- ③は上記で確定。実装時は「おすすめ」を流用し、表示を2列×5に変更する。

## 実装時の参照

- **①** と **③** は確定。**②** は設計案を doc に固定し、実装前にもっと詰める。
- 実装の進め方: **まず ①・②（表面上だけ）・③ を実装する。**  
  - ①: アルゴリズム（Sタグ・有名/無名・最大10作品）をバッチリ。  
  - ②: 表面だけ。Stage・1問だけ・thinking・結果への流れ。②の内部（タグプール絞り・動的10タグ等）はあとから。  
  - ③: 結果表示を2列×5・おすすめ流用でバッチリ。
- プレイモードで使っている **Stage・背景・白板・キャラ・質問→thinking→次** の流れを共通化し、変更するのは **質問文言・答え方・白板サイズ** に限定する。
