# 差分分析: v1.5 設計 → 問題固定先行 v2

**対象**
- 旧: `docs/DESIGN-new-tag-special-noise-v1.md`
- 新: `docs/DESIGN-problem-first-v2.md`

---

## 1. 総評

v1.5 は「質問種類の整備」に強い一方、改善の本丸である **P0課題（DB外作品、早期見切り、弾切れ）** が弱かった。  
v2 は「問題定義を先に固定」し、手段先行を防ぐ構造へ変更している。

---

## 2. 主要差分（削除/維持/追加）

| 区分 | v1.5 | v2 |
|------|------|----|
| 主軸 | 新タグ/特別質問/ノイズの仕様中心 | P0/P1/P2問題固定中心 |
| DB外作品対応 | 記述はあるが補助扱い | **P0-1として最優先** |
| 早期分岐 | 方針記述のみ（詳細弱い） | **P0-2として分岐主軸化** |
| 弾切れ問題 | 間接的に触れるのみ | **P0-3として明示** |
| 新タグ質問 | 詳細仕様あり | 維持。ただし**補助手段へ格下げ** |
| ノイズ誘導 | 条件・出題の詳細あり | 維持。推薦統合の文脈へ |
| 成功判定 | チェックリスト中心 | **数値指標を明示** |
| 非目標 | ほぼ未定義 | **やらないことを明記** |
| API契約 | 暗黙 | **`/api/works/search` と `/api/failhub/select` を定義** |
| Config設計 | 既存中心 | **`flow.earlyExitReview` / `failHub` を追加定義** |
| 実装責務 | 断片的 | **ファイル単位で責務を明示** |

---

## 3. 「忘却」を防ぐための構造変更

### v1.5の弱点

- 仕様は精密だが、なぜそれをやるかの重みづけが弱い
- 新タグなどの実装しやすい手段が先行し、P0の論点が後段に流れやすい

### v2の対策

- 文書先頭で目的とP0課題を凍結
- 各課題に「現象/原因/悪影響/解決/成功判定」を必須化
- 実装順をP0→P1→P2に固定

---

## 4. 実装順の差分

### v1.5寄りの順序

1. 質問仕様を整える  
2. ノイズ/新タグを追加  
3. 早期分岐・検索を後続

### v2の順序（採用）

1. 早期分岐 + 失敗ハブ遷移  
2. タイトル部分検索 + 失敗UI  
3. 新タグ/ノイズ最適化  

結論: 「当てられない時の価値提供」を先に作る。

---

## 5. 現行実装に対する影響メモ

- `src/server/game/engine.ts`  
  - Q25/30/35/40審査の明確な状態遷移定義が必要
- `config/mvpConfig.json`  
  - 詰み判定閾値の正式セクション追加が必要
- `src/app/...` fail系UI  
  - 候補表示と部分検索の統合導線が必要
- `src/server/config/schema.ts`
  - `earlyExitReview` / `failHub` のスキーマ追加が必要
- `src/app/api/works/search/route.ts`（新規）
  - reserve込み部分一致検索APIが必要
- `src/app/api/failhub/select/route.ts`（新規）
  - 失敗時選択保存APIが必要

---

## 6. 移行判断（Go/No-Go）

実装着手は以下が埋まってから。

1. P0-1〜P0-3の検知/遷移/保存仕様が確定
2. 失敗ハブの画面責務が確定
3. 運用DB外3万件検索のデータソースが確定
