# 本番公開ロードマップ

2026-02-27 作成。Opus 分析に基づく包括的ロードマップ。
成功率改善・パイプライン効率化・サービス向上・全体整備の 4 領域。

---

## 0. 現状サマリー

| 指標 | amb.1 | amb.3 |
|------|-------|-------|
| DB 作品数 | 5,846（ゲーム有効） |
| 成功率 | 91% | 83% |
| 平均 Q（成功時） | 15.3 | 20.0 |
| pop35+ 成功率 | 96%（平均 14.2Q） | 97%（平均 18.0Q） |
| pop15-34 成功率 | 98%（平均 15.2Q） | 93%（平均 20.7Q） |
| pop0-14 成功率 | 73%（平均 17.3Q） | 52%（平均 22.4Q） |
| Special Question | 6 種（SERIES / POPULARITY / TITLE_CHAR_TYPE / TITLE_SYLLABLE / AUTHOR_CHAR_TYPE / TITLE_SYLLABLE_2） |

**達成済み**: メジャー作品を少ない質問数で当てる。pop35+ で平均 14Q、81% が 15 問以内。
**残課題**: pop0-14（マイナー作品）の構造的失敗（~6%）と、ノイズ駆動失敗。

## 1. 成功率改善（アルゴリズム + データ品質）

### 1-1. titleReadingInitial の全作品追加 ★最優先

| 項目 | 内容 |
|------|------|
| 現状 | 漢字始まり 59% の作品は null → DONT_CARE 扱い |
| 効果 | TITLE_SYLLABLE の情報量が ~0.5 bit → ~1.0 bit に倍増 |
| 方法 | AI タグ付けパイプラインに「タイトル読みの先頭 1 文字をカタカナで返せ」を追加 |
| 備考 | 構造的失敗に最も刺さる。タグに頼らない追加情報源 |

### 1-2. 問題作品の特定と修正ワークフロー

```
Step 1: 全作品シミュ (amb.1) → 構造的失敗 350〜400 件を特定
Step 2: 失敗作品のタグ自動分析 → 独自性スコアで修正候補を抽出
Step 3: 修正で救える作品を優先 → タグ 1〜2 個追加で効果大
Step 4: titleReadingInitial 追加後に再テスト
Step 5: 残りを手動修正 → 1% 目標達成
```

- 10,000 件で問題作品 ~100 件以内が目標
- タグ修正は 10,000 件到達後にまとめて対応

### 1-3. 双子問題対策 — シリーズ内 REVEAL 回避

- REVEAL MISS した work の seriesInfo を取得し、同シリーズ他作品の重みを一括ペナルティ
- 同シリーズで 3 回 REVEAL を浪費する問題を防ぐ

### 1-4. フェーズ別イプシロン ✅ 実装済み

- 前半 (EC>200): 0.03 / 中盤: 0.05 / 後半 (EC<20): 0.08
- コンフィグで調整可能にした

### 1-5. POPULARITY 閾値

- 現在 25。30 への変更は差が 0.06 bit と微小。ゲーム体験で判断
- 推奨は 30 だが、優先度は低い

## 2. パイプライン効率化（10,000 件到達の加速）

### 現状のボトルネック

| 処理 | 現在の方式 | 1,000 件の所要時間 |
|------|-----------|-------------------|
| コメント取得 | Puppeteer 逐次, 1s 間隔 | ~40-50 分 |
| AI Phase1（タグ付け） | API 逐次, 3s 間隔 | ~70-80 分 |
| AI Phase2（チェック） | API 逐次, 3s 間隔 | ~70-80 分 |
| その他（DB 書き込み等） | — | ~30-40 分 |
| **合計** | | **~8 時間（エラー含む）** |

### 2-1. 並列化 ★★★ 最大効果

- コメント取得: Puppeteer concurrency を 1 → 3-5 に
- AI API 呼び出し: 3-5 並列（GPT-5 mini のレート制限は十分余裕あり）
- **これだけで 1,000 件が 2-3 時間に短縮**

### 2-2. フェーズのパイプライン化

- 現在: Phase1 を全件完了 → Phase2 を全件完了
- 改善: Phase1 が 50 件完了 → その 50 件の Phase2 を開始しつつ Phase1 を継続
- 全体で 30-40% 短縮

### 2-3. チェックポイント / リジューム機能

- 各作品の処理状態を DB に記録（commentFetched, phase1CompletedAt, phase2CompletedAt）
- 中断しても「未処理分だけ」を自動で再開
- エラー作品だけリトライ可能

### 2-4. バックグラウンド実行

- 別プロセスで実行し、進捗を JSON/SQLite に書き出す
- 管理画面の ProgressPanel で進捗確認
- 寝ている間に完了させる運用

### 目標時間

| 施策適用後 | 1,000 件の目標時間 |
|-----------|-------------------|
| 5 並列化 | **~2 時間** |
| + パイプライン化 | **~1.5 時間** |
| + リジューム | エラーロス → ほぼゼロ |
| + バックグラウンド | 放置で完了 |

**残り ~4,000 件は一晩（8-10 時間）で処理可能。**

## 3. サービス向上（体験 + 収益）

### 3-1. 「正解に近づいている」演出 ★★★ 最優先

effectiveCandidates をフロントに渡し、段階的リアクション:

| 段階 | 条件（目安） | キャラ表情 | テキスト例 |
|------|-------------|-----------|-----------|
| 序盤 | EC > 500 | 通常 | 「うーん……」 |
| 中盤 | EC 50-500 | 少し自信 | 「なんとなく見えてきた…」 |
| 終盤 | EC 10-50 | 目が光る | 「おっ……これは……！」 |
| 確信 | EC < 10 | ニヤリ | 「わかったかも……！」 |

- サーバー側変更はほぼ不要。Stage コンポーネントに confidenceLevel を追加
- キャラ画像を 2-3 枚追加

### 3-2. OG 画像動的生成 + X 投稿改善 ★★★

**X 投稿テキスト（作品名なしベース）:**
```
【ERONATOR】○○問で当てられた！ あなたの妄想、エロネイターが当ててみる？
#エロネイター
```

**OG 画像:**
- `@vercel/og` で動的生成: `/api/og?q=15&result=success`
- 「15 問で当てた！」のデザインカード画像
- 作品名は含めない。リンク共有時に自動表示
- オプションで作品名を含めるモードも用意

### 3-3. 配信者モード ★★☆

| 対象 | 通常モード | 配信者モード |
|------|-----------|-------------|
| 質問文 | そのまま | 抽象化（streamSafeText） |
| サムネイル | 作品画像 | 非表示 or シルエット |
| タグ表示 | そのまま | 抽象化 |

- URL パラメータ `?mode=stream` で起動、Cookie で保持
- タグ DB に `streamSafeQuestionText` カラムを追加
- AI で一括変換可能

**配信者モードは「機能」ではなく「マーケティングチャネル」。**
一人の配信者の視聴者数千〜数万人にリーチできる。

### 3-4. Success 画面の CTA 改善 ★★☆

- 「FANZA で見る」→「今すぐ読む」「サンプルを見る」
- レビュー情報の表示: `★4.8（128 件）`
- おすすめの理由表示: 「同じ作者の人気作」「似たジャンルの高評価作」
- ボタンを大きく、FANZA カラー（オレンジ系）で目立たせる

### 3-5. 推薦モード ★★☆

TopScreen に既に UI ボタンあり（disabled）。

**フロー:**
```
好みの選択（4 択 × 3-5 問、複数選択可）
  → 候補の絞り込み（タグベースフィルタ + 有名度ソート）
  → 結果表示（「有名おすすめ」と「隠れた名作」のセクション分け）
  → 各作品に FANZA リンク
```

- 通常モード Success 画面から「あなたの好みに合った作品をもっと見る？」で誘導
- 通常モードでもおすすめ 5 件を提示済み。推薦モードはより能動的な「探す」体験

## 4. 全体整備

### 4-1. セキュリティ

- 管理画面: 本番で 404 → ✅ 対応済み
- **要確認**: `/api/admin/*` ルートも本番で保護されているか
- **要確認**: `NEXT_PUBLIC_` 変数に秘密情報が含まれていないか

### 4-2. パフォーマンス

- workTagMatrix.json: 10,000 件で現状の ~2 倍に肥大化
- Vercel サーバーレスのメモリ制限（128-1024MB）に注意
- コールドスタート時のマトリックスロード時間を監視

### 4-3. 収益最大化

- Success 画面の CTA 最適化（上記 3-4）
- 推薦モードによるクリック機会増（上記 3-5）
- FANZA クリック追跡は実装済み → データ分析で改善サイクルを回す
