# 設計書：新タグ質問・特別質問（タイトル長）・ノイズ誘導

**版**: v1.5（Q12＝タイトル第2枠・新タグ3本目は13・ノイズ条件の言い切り）  
**日付**: 2026-04-02  
**目的**: 実装担当がこの文書だけで着手できる粒度にする。

---

## 0. 用語

| 用語 | 意味 |
|------|------|
| 質問番号 | ユーザーに見える「何問目か」。1 始まり。コードでは `questionIndex` または `qIndex`。 |
| 新タグ質問 | 回答で新規タグ（または同等のフラグ）をセッションに紐づける、探索タグとは別系統の質問。 |
| 特別質問 | `SPECIAL_QUESTION`。`selectSpecialQuestion` が選ぶタイプ。 |
| **タイトル系3種（ノイズ判定のプール）** | **`TITLE_CHAR_TYPE`**（先頭文字種）、**`TITLE_SYLLABLE`**（行）、**`TITLE_LENGTH_STYLE`**（タイトル長・なろう系っぽさ。§2.1）。 |
| **タイトル系2回（出題保証）** | **Q5（行）＋ Q12（長さ or 文字種のどちらか）** の **2問**（§0.2）。 |

## 0.1 現状の実装（コードベース・2026-04 時点）

設計書の「細かい特別質問」は `specialQuestionSelection.ts` と `engine.selectNextQuestion` で次のとおり動いている。**本節はリプレイ用の「変更前」事実**。

**スロット**

- `mvpConfig.flow.specialQuestionSlotIndices` = **3, 5, 9, 16**。  
- 特別質問で **UNKNOWN** が既に出ている場合、**11** も特別質問枠に追加される。  
- **救済**: `rescueSpecialCondition` で **20, 24**。条件（実効候補数・信頼度）を満たすときだけ。

**プール（変更前）**

- **Q3**: `SERIES` か `POPULARITY` のみ。  
- **Q5**: Q3 で使わなかった方に **`TITLE_CHAR_TYPE`** を足した候補から選ぶ。  
- **Q9 / Q16 / Q11**: 四種から未使用を選ぶ。  
- **Q20 / Q24（救済）**: `AUTHOR_CHAR_TYPE`、条件付きで `TITLE_SYLLABLE_2`。

**未実装（引き続き）**

- **`TITLE_LENGTH_STYLE`**（型・`processAnswer`）。  
- **ノイズ質問**（`NOISE_GUIDE_RECOMMEND` 等）。  

**以降の実装は §0.2 に従う。**

## 0.2 特別質問スロット（確定案・PO）

**意図**: **`TITLE_SYLLABLE`（1回目の行）を先に必ず出す**ことで、**`TITLE_SYLLABLE_2`（救済）の前提**が崩れにくくする。  
**Q11 の扱い**: 既存どおり **「特別質問に UNKNOWN が出たあとにだけ追加される補填枠」** に使う（動的）。**固定のタイトル第2問は Q11 には置かない**（補填と番号が被るため）。**タイトル第2枠は Q12** に置く（当初「新タグ3本目を 12 に」と書いたのと同じ発想＝**Q11 を空けて衝突を避ける**）。

| 質問番号 | 内容（確定） |
|----------|----------------|
| **Q3** | **`SERIES` と `POPULARITY` のどちらか**（**Q9** と合わせて **両方必ず1回ずつ**） |
| **Q5** | **`TITLE_SYLLABLE` 固定**（50音・行） |
| **Q9** | **`SERIES` と `POPULARITY` の、Q3 で出なかった方** |
| **Q11** | **固定コンテンツは置かない**。既存ロジックどおり **UNKNOWN 補填**でこの番号が特別枠に乗ることがある（動的）。 |
| **Q12** | タイトル系 **残り2種** — **`TITLE_LENGTH_STYLE` と `TITLE_CHAR_TYPE` のどちらか1つをランダム** |
| **Q16・Q20・Q24** | **救済に近い条件付き枠**。条件・出題タイプの中身は **`mvpConfig` に委ねる**（下記）。実装後も **コンフィグだけ変えれば調整できる**形にする。 |

**救済枠（Q16 / Q20 / Q24）のコンフィグ**

- **細かい閾値・優先順位・どのタイプを出すか**は、設計書で固定せず **実装担当に一任**。  
- 既存の `flow.rescueSpecialCondition` と同様に、**`mvpConfig`（必要なら新セクション）** に載せ、**後から数値・種別を変えられる**こと。  
- 想定されるタイプ: **`TITLE_SYLLABLE_2`**（条件付き）、**`AUTHOR_CHAR_TYPE`**、必要なら **`TITLE_LENGTH_STYLE`** など。

**ノイズ判定（§3）との関係（言い切り）**

- ノイズの条件は **「わからないに2回答えた」という数え方ではなく**、**次の2つの質問それぞれに対する回答が UNKNOWN であること**:  
  1. **Q5**（`TITLE_SYLLABLE`）への回答が **UNKNOWN**  
  2. **Q12**（`TITLE_LENGTH_STYLE` または `TITLE_CHAR_TYPE`）への回答が **UNKNOWN**  
- この2つを満たしたあと、**次の1問**でノイズ（§3）。ノイズは **他の差し込みより優先**（§3.2）。

## 1. 新タグ質問（3 種・挿入 3 スロット）

### 1.1 内容（確定）

ランダムに出すのは **どの種類か** のみ。3 スロットそれぞれで、**未だ出していない種類の中からランダムに 1 つ**（3 スロットで必ず 3 種すべて出る）。

| ID | 質問文（案・コンフィグ化可） | 付与するタグ名（DB 上の新タグ） |
|----|------------------------------|----------------------------------|
| NT1 | 舞台は現代日本？ | **現代日本** |
| NT2 | 主人公は男性？ | **男主人公** |
| NT3 | 原作がある？ | **原作アリ**（既存「オリジナル」タグは**無視**し、本タグを別物として扱う） |

### 1.2 挿入位置（確定）

| スロット | 質問番号 | 備考 |
|----------|----------|------|
| A | **2** | 本設計では **新タグ質問を最優先**（その回は通常 Q2 ロジックは実行しない）。 |
| B | **7** | 競合しにくい。 |
| C | **13**（既定） | **Q12 はタイトル第2枠（§0.2）のため**、新タグ 3 本目は **13** にずらす。番号は **`mvpConfig.newTagQuestions.slotIndices`** 等で変更可。 |

### 1.3 実装上の `kind`

- 既存の `EXPLORE_TAG` に載せるか、専用 `kind: 'NEW_TAG_QUESTION'` を追加するかは実装側で選ぶ。  
- いずれにせよ **tagKey または専用 ID** で 3 種を識別し、`processAnswer` で重み更新・履歴保存できること。

### 1.4 回答と重み（確定方針）

- YES / NO / UNKNOWN の扱いは **通常のタグ探索と同様の方針**（ベイズ更新の有無は既存アルゴリズムに合わせる）。  
- UNKNOWN は「情報が得られない」扱いでよい（仕様は既存 UNKNOWN と揃える）。

**導入直後・データ面の注意（重み更新）**

- 新タグは **作品に未付与のまま**運用が始まるため、当該タグに紐づく重み更新は **実質ノーオペレーションに近い** か、効果が限定的になりうる。  
- これは **仕様として許容**する。  
- シミュレーションでは新タグ質問の回答を **常に UNKNOWN** に固定する（§7）。**スロット番号は既定で 2, 7, 13**（実装時に `isNewTagQuestionForSimulation` の判定を合わせる）。

### 1.5 作品への「タグ付け」自動化（保留・本リリースはスルー可）

以下は **仕様として確定しない（保留）**。

| 案 | 内容 |
|----|------|
| **失敗時・リスト／検索で正解を選んだとき** | 選択 `workId` へ新タグを **自動で DB 付与**する、など。 |
| **正解時** | 正解作品へ **自動タグ付与**。 |

**方針**

- まずは **セッション内の重み・履歴のみ**で完結。  
- **誤データや運用事故につながる実装になりそうなら、本リリースでは DB 自動タグ付けは入れない（スルー）でよい。** 必要になった時点で §1.5 を再オープンし、ポリシーを決めてから実装する。

## 2. 特別質問：タイトル長（なろう系っぽい）

### 2.1 仕様（確定）

- **質問文（案）**: 「なろう系みたいに長いタイトル？」（`specialQuestions.json` に追加）  
- **新しい特別質問タイプ**（案）: `TITLE_LENGTH_STYLE`

**判定（作品ごと）**

- **YES** → タイトル **10 文字以上** に重みを寄せる（いいえ側はペナルティ）。  
- **NO** → **20 文字以内** に重みを寄せる。

### 2.2 救済スロットとの関係

- **Q16 / Q20 / Q24** は §0.2。**中身は `mvpConfig` に一任**（§0.2 参照）。  
- **`TITLE_SYLLABLE_2`** は **`TITLE_SYLLABLE`（Q5）が YES/NO で終わっていること**が前提。

### 2.3 ノイズ条件の整理

- **Q5 と Q12** の **2問それぞれの回答が UNKNOWN** → §3 のノイズ（上記 §0.2 と同じ）。

### 2.4 本節は §0.2 への参照

特別質問の **番号とタイプの対応**は **§0.2 の表**を正とする。

## 3. ノイズ誘導（1 種のみ）

### 3.1 採用しないもの

- 「同人誌だよね？ちゃんと答えてる？」→ **実装しない**。

### 3.2 採用するもの（確定）

**質問文（案）**: 「もしかして…特定の作品やタイトルにこだわりがない？」

**挙動（確定）**

- **YES** → **RecommendMode の最初の画面**。**URL 直打ちではない**。**トップへ飛ばさない**。

**出現条件（確定）**

- **Q5 と Q12** のタイトル系2問が **それぞれ UNKNOWN** のあと、**直後の1問**で出す（§0.2）。

**差し込み優先度（PO 確定）**

- ノイズは **新タグ枠・UNKNOWN 補填などより優先**（`selectNextQuestion` 内で順位を固定）。

**デバッグ（PO 確定）**

- **成功 / 失敗 / 惜しかった** 等から **推薦モード先頭**へ飛ばすショートカット（デバッグ用）。

**Q20 フォールバック**（任意）

- ノイズが未出のまま進んだ場合の保険は実装判断でよい。
