# 有名作品帯の正解率・体感検証（Top100 相当）

**目的:** 「有名な作品は少ない質問で当てる」というプロダクト目標と、実際の挙動が揃っているかを確認する。

## 1. 「Top100」の定義

コード上は `Work.popularityBase` / `popularityPlayBonus` やシミュレーション対象の並びで人気が表現されます。検証時は次のいずれかで固定すると再現性が出ます。

1. **DB で人気上位を抽出**（例: `popularityBase + popularityPlayBonus` の降順で 100 件の `workId` をメモする）
2. **管理画面のシミュレーション**で「人気帯のみ」「特定 workId リスト」など既存フィルタがあればそれに合わせる（UI は [admin/tags/page.tsx](../src/app/admin/tags/page.tsx) 周辺）

## 2. シミュレーションで見る指標

- 各 `workId` について: **質問数**、**SUCCESS / FAIL_LIST / 早期終了** の比率
- 早期終了ステップと [mvpConfig.json](../config/mvpConfig.json) の `flow.earlyExitReview` の整合（管理のシミュ列・閾値サマリ）

## 3. 実プレイでの体感チェック

1. 上で決めた **有名 10〜20 本**だけを手元リストにする
2. 本番またはステージングで **同じ作品を複数回**（回答パターンを少し変えて）プレイする
3. メモする項目:
   - 何問で REVEAL になったか
   - YES で正解できたか / FAIL_LIST に落ちたか
   - 「惜しい」と感じたか（主観）

## 4. ズレていたときの手順

1. まず **タグ欠損・ノイズ**（その作品の `WorkTag`）を疑う → 管理の手動タグ付けで修正
2. 次に **閾値・flow**（`mvpConfig.json` の `algo` / `flow` / `confirm`）をシミュ結果に合わせて調整
3. 変更後は `npx tsc --noEmit` と、可能ならシミュの再実行

## 5. 記録の仕方（推奨）

スプレッドシートまたは issue 1 本に、`workId` / タイトル / シミュ問数 / 実プレイ問数 / メモ の列を用意し、リリース前に毎回同じシートを更新する。
