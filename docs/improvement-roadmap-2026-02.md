# 改善ロードマップ（Opus 分析ベース）

2026-02-27 時点。Opus によるシミュレーション分析結果を簡易ロードマップにまとめた。

---

## 1. 現状サマリー

| 指標 | amb.1 | amb.3 |
|------|-------|-------|
| 成功率 | 91% | 83% |
| 平均Q（成功時） | 15.3 | 20.0 |
| pop35+ 成功率 | 96% | 97% |
| pop15-34 成功率 | 98% | 93% |
| pop0-14 成功率 | 73% | 52% |

**評価**: メジャー作品を少ない質問で当てる目標はほぼ達成。pop35+ は amb.1 で平均 14.2Q、81% が 15 問以内。

**※ シミュ条件**: workTagMatrix が最新の状態での結果。workTagMatrix が古いと（DB の作品数と行列の件数が乖離）、タグなし作品が多数含まれ成功率が大幅に低下する（例: 500件シミュで 66%）。シミュ前に `npm run generate:worktag-matrix` を実行すること。

---

## 2. うまくいっていること

- **Special Question 6 種**: いずれも YES 率 20〜50% で情報量を提供
- **救済機構**: amb.3 で約 40% の試行で発動し、苦戦するほど発動する設計が正しく動作
- **POPULARITY 閾値 30**: 文言「かなり有名？」に合致。変更不要

---

## 3. 残る問題

### 3.1 構造的失敗（pop=0、約 6%）

- **原因**: タグが「ありふれている」（中出し、巨乳、フェラ等、DB で数千件）
- **特徴**: タグ数 4〜10、独自性のあるタグが不足
- **結論**: アルゴリズムより**データ品質**が原因

### 3.2 双子問題（同シリーズ誤推定）

- 例: 「母さんじゃなきゃ〜4 後編」vs「〜4-6+総集編」
- REVEAL MISS 後に同シリーズの別巻をまた推定してしまう

### 3.3 惜敗（rank 86, 120 など）

- pop=13/15 の作品で、特異なタグ構成による失敗

---

## 4. 改善提案（優先度順）

### P1: titleReadingInitial の全作品追加 【最優先・効果大】

| 項目 | 内容 |
|------|------|
| 現状 | 漢字始まり 59% の作品は null → DONT_CARE 扱い |
| 効果 | TITLE_SYLLABLE の情報量が約 0.5 bit → 1.0 bit に倍増 |
| 工数 | 中（バッチ + 管理画面での確認） |
| 備考 | 構造的失敗に最も刺さる（タグに頼らない追加情報源） |

### P2: 問題作品の特定と修正ワークフロー 【ROI 高】

| 項目 | 内容 |
|------|------|
| Step 1 | 全作品シミュレーション（amb.1, 約 5,800 件）→ 失敗リスト取得 |
| Step 2 | 失敗作品のタグを自動分析（独自性スコア算出） |
| Step 3 | 「修正で救える」作品を優先（タグ 1〜2 個追加で効果大） |
| Step 4 | titleReadingInitial 追加後に再テスト |
| Step 5 | 残りを手動修正 → 1% 目標達成 |

### P3: 双子問題対策 — シリーズ内 REVEAL 回避

| 項目 | 内容 |
|------|------|
| 仕組み | REVEAL MISS した work の seriesInfo を取得し、同シリーズ他作品の重みを一括ペナルティ |
| 効果 | 同シリーズで 3 回 REVEAL を浪費するのを防ぐ |
| 工数 | 小〜中 |

### P4: フェーズ別イプシロン（検討レベル）

| フェーズ | epsilon | 狙い |
|----------|---------|------|
| 前半 (EC>200) | 0.03 | 攻めの絞り込み |
| 中盤 (20<EC<200) | 0.05 | 現状維持 |
| 後半 (EC<20) | 0.08 | ノイズ耐性重視 |

- 効果: amb.3 で +2〜3% 程度の見込み
- リターンは限定的。優先度は低め

---

## 5. 1% 問題作品目標への道筋

```
Step 1: 全作品シミュ (amb.1)     → 構造的失敗 350〜400 件を特定
Step 2: 失敗作品のタグ自動分析   → 独自性スコアで修正候補を抽出
Step 3: 修正で救える作品を優先   → タグ 1〜2 個追加で効果大
Step 4: titleReadingInitial 追加 → 再テスト（構造的失敗 3〜4%→2% 推定）
Step 5: 残り 2% を手動修正      → 1% 目標達成
```

---

## 6. 総合評価

- **アルゴリズムの改善余地はほぼ限界に近い**
- 次のフェーズは**データ品質**へのシフト
- 優先度 1: titleReadingInitial 全作品追加
- 優先度 2: 全作品シミュで問題作品特定
- 優先度 3: 問題作品のタグ修正

この 3 ステップで、10,000 作品でも全体成功率 85%+（amb.3）は十分到達可能と見る。
