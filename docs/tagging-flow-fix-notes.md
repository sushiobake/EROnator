# タグ付けフロー変更のメモ（解消するもの／保証できないもの）

**作成日: 2026-02**

---

## 何を変更したか

- **ManualTagging.tsx** の「AIにタグ付けさせるためのコピペ」が、旧フロー（`cursor-analysis-untagged-10-batchN.json` + `apply-cursor-legacy-ai-batch.ts`）を渡していた
- これを新フロー（`tagging-pending.json` + `apply-tagging.ts`）に統一した
- `legacy-ai-tagging-instruction.md` と ManualTagging のコピペ指示が矛盾していたのを解消した

---

## 変更の結果、何がどうなるか

| 項目 | 旧フロー | 新フロー |
|------|----------|----------|
| 保存先 | 例: `cursor-analysis-untagged-10-batch14.json`（毎回名付けが必要） | `tagging-pending.json`（固定） |
| 実行コマンド | `apply-cursor-legacy-ai-batch.ts 保存したファイル名.json`（ファイル名の指定が必要） | `apply-tagging.ts`（引数不要） |

**結果**:
- 保存先が固定になり、「どのファイルを apply するか」の迷いがなくなる
- 実行コマンドが 1 つに固定され、ファイル名の打ち間違い・指定ミスがなくなる
- 指示書とコピペが一致し、GPT が矛盾した指示のどちらを優先するかで迷わなくなる

---

## 今回の変更で解消されるミス（想定）

1. **指示の矛盾によるミス**: コピペの 4・5 が旧フローだったため、GPT が「cursor-analysis-untagged-10-batchN.json に保存し、apply-cursor-legacy-ai-batch.ts を実行せよ」と指示していた。指示書（legacy-ai-tagging-instruction.md）は新フローだったため矛盾しており、GPT が短い指示を優先して旧フローで動いていた。**この矛盾は解消される。**

2. **ファイル名の指定ミス**: 旧フローでは「保存したファイル名」を apply コマンドに渡す必要があった。バッチ番号や拡張子の打ち間違いで apply が失敗する可能性があった。**新フローではファイル名指定が不要になる。**

3. **apply 実行対象の取り違え**: 複数の JSON があるときに、どれを apply するか間違える可能性があった。**新フローでは tagging-pending.json が常に 1 つなので取り違えがなくなる。**

---

## 保証できないこと

以下は **今回の変更では保証・解消できない**。

1. **GPT が指示に従うかどうか**  
   GPT が「tagging-pending.json に保存せよ」と指示されても、別の場所・名前で保存する可能性は残る。モデルの挙動に依存する。

2. **apply の実行忘れ**  
   指示通り「apply-tagging.ts を実行せよ」と渡しても、ユーザーや Cursor が実行し忘れる可能性は残る。運用側の確認が必要。

3. **Custom GPT など別の指示源**  
   ユーザーが Custom GPT や別のプロンプトに古い指示を保存している場合、このプロジェクトの変更は反映されない。**渡している指示の出所が 1 つであること**を確認する必要がある。

4. **タグ品質の問題**  
   新規タグの使用、S と A の入れ違い、キャラ名の誤りなど、**タグ付けの内容に関するミス**は今回のフロー変更では触れていない。別途、指示書のルール強化やチェックで対応する。

5. **apply-tagging.ts の実装バグ**  
   スクリプト自体にバグがある場合は、フローを正しく使っても失敗する。必要に応じて動作確認すること。

## 結論

- **「指示の矛盾」と「ファイル名・実行コマンドの指定ミス」は、今回の変更で解消される想定である。**
- **「もうミスらない」は保証できない。** 上記「保証できないこと」に当てはまる事象は残る。
- 100 件試すような運用では、**今回の変更後も 1〜2 回は目視で確認**し、想定通り動いているか確認するのが安全である。
